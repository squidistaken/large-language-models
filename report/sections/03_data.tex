\section{Data and Task Setup}
\label{sec:data}

\subsection{XED for English and Croatian}
\label{sec:data_xed}

We used the English and Croatian portions of XED, keeping Plutchik's eight labels, in a fixed order, from data preparation through to evaluation. Neutral lines are not part of the task, so every line carries at least one emotion. To build matched pairs, we linked every Croatian line to an English line through XED's subtitle alignments. Of the 5,422 pairs left after cleaning, 2,236 are aligned directly (one hop). For the other 3,186, XED links the Croatian line only to a Danish subtitle, and we reached the English line through Danish (two hops). Where a Croatian line had several English counterparts, we preferred one with a human annotation, then the one with the fewest hops. The English side carries XED's human labels for 5,247 pairs (96.8\%); the other 175 English lines take the projected labels of their Croatian counterpart. Since the two languages' labels come from different files, they can differ within a pair. For every line, we recorded the number of hops and the source of its labels, which we later use to separate model errors from alignment and projection errors.

Anger and anticipation are the most frequent emotions, each on about a quarter of the lines, and disgust is the rarest, on about one line in eight; a Croatian line carries 1.45 emotions on average (Figure~\ref{fig:label-distribution}).

\subsection{Split and Leakage Controls}
\label{sec:data_split}

XED's Croatian file has 5,941 labelled lines once three malformed rows are removed. Of these lines, one could not be aligned to any English subtitle. We detected duplicates after normalising Unicode, case, punctuation and spacing, which differ between XED files, and kept only the first of 518 repeated Croatian lines. This leaves 5,422 English--Croatian pairs. English lines can still repeat, because different Croatian lines are sometimes aligned with the same English text (612 English lines occur in more than one pair), so we grouped the pairs that share an English line and assigned each group to a single partition. No line, in either language, therefore appears in more than one partition.

We made one fixed 70/20/10 training, development and test split with seed 42. Pairs were assigned by their XED alignment identifier before the English and Croatian files were written, which keeps both versions of a subtitle in the same partition. To keep each emotion's share similar across partitions, we used iterative multi-label stratification \parencite{sechidis2011stratification}, as implemented in \texttt{iterstrat}, on the Croatian labels merged over each group, since every pair has a Croatian label set, whereas 175 English lines borrow theirs. The training set was split off first, and the remaining 30\% was divided 2:1 into development and test sets. This gave 3,803 training, 1,068 development and 551 test lines per language, with each emotion's share differing by at most 2.3 percentage points between the Croatian partitions and 2.7 between the English ones (Table~\ref{tab:split-support}). All design decisions were made on the development set, the test set was used only for the final evaluation, and the five-shot demonstrations were drawn from the training set only.

\subsection{Data Formatting}
\label{sec:data_formatting}

Every pair was written out in a conversational format of three messages. The system message lists the eight permitted labels in the fixed order, each with a one-line definition, states that every line expresses at least one of them and may express several, and asks for a JSON list of the matching label names and nothing else. The user message holds the subtitle, as \texttt{Subtitle: \{text\}}, and the assistant message holds the reference labels as a JSON list, for example \texttt{["anger", "fear"]}. Croatian examples use the same English instruction and label names, giving both languages the same output format, parser and metrics. Fine-tuning trains the model to produce the assistant message, while prompting lets it generate the message itself. With the same files serving both approaches, zero-shot prompting sees the same input as the fine-tuned models.
